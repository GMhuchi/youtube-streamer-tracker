# 유튜브 스트리머 라이브 트래커 (API 키 불필요)

등록해둔 유튜브 채널들이 지금 방송 중인지 5~10분마다 자동으로 확인하고,
지정한 검색어(태그)로 새로 방송을 시작한 스트리머도 찾아서 한 페이지에
보여주는 완전 무료 트래커입니다.

- **유튜브 공식 API(Data API v3) 키가 전혀 필요 없습니다.** 대신 로그인 없이도
  볼 수 있는 유튜브의 공개 페이지(채널 RSS, 채널 '실시간' 탭, 검색결과
  페이지)를 직접 읽어서 정보를 뽑아냅니다.
- **완전 무료 호스팅**: GitHub Actions(스케줄 실행) + GitHub Pages(정적
  페이지 호스팅)만 사용합니다. 공개 저장소면 둘 다 무제한 무료입니다.
- **등록도 삭제도 페이지에서**: "＋ 채널 등록" / "－ 채널 삭제" 버튼을 누르면
  각각 GitHub 이슈 폼이 열리고, 입력만 하면 자동으로 처리되어 이슈가 닫힙니다.
  GitHub 계정만 있으면 되고, 저장소 코드를 직접 건드릴 필요는 없습니다.
- **방송 이력 기록**: 각 채널이 언제 방송을 켜고 껐는지 세션 단위로 쌓이고,
  오늘·이번 주·이번 달 누적 방송 시간을 한국 시간(KST) 기준으로 집계합니다.
  이터널리턴 방송만 따로 걸러서 볼 수도 있습니다 (`docs/history.html`).
- **시청자수 추이**: 방송 중에는 동시 시청자수를 사이클마다 기록해서,
  채널을 누르면 그 방송의 시청자수 그래프와 평균/최고 시청자수, 지난
  방송 목록을 볼 수 있습니다. 평균은 방송 길이로 가중해서 계산합니다.
- **이터널리턴 방송 채널 자동 추적**: 태그 검색에 걸린 미등록 채널 중, 실제로
  이터널리턴을 방송 중인 채널은 자동으로 등록되어 그때부터 이력이 쌓입니다.
  검색어에만 걸린 다른 게임 방송은 워치 페이지의 게임/제목을 확인해 걸러냅니다.

## 이 방식의 한계 (꼭 읽어주세요)

공식 API를 쓰지 않는 대신 얻는 트레이드오프입니다.

1. **비공식 방식입니다.** 유튜브가 페이지 구조를 바꾸면 파싱이 깨질 수
   있습니다. 이 저장소의 `scripts/common.py` 안의 파싱 로직만 고치면
   되도록 최대한 한 곳에 모아뒀습니다. 실행이 실패해도 전체가 죽지 않고
   `docs/status.json`의 `warning` 필드에 무엇이 실패했는지 남깁니다.
2. **너무 자주/많이 확인하면 유튜브 쪽에서 요청을 의심할 수 있습니다.**
   기본값은 10분 간격, 태그 2~4개, 1시간마다 검색입니다. 등록 채널이
   20개면 한 사이클에 20번 정도 요청하므로, 채널이 더 늘어나면
   `.github/workflows/track.yml`의 cron 간격을 늘리세요.
   최근 영상 정보(RSS)는 부가 정보라서 2시간마다만 확인하고,
   실패해도 사이트에 경고를 띄우지 않고 실행 로그에만 남깁니다.
3. **검색(태그 디스커버리)은 유튜브 검색결과 페이지를 그대로 읽는 것이라,
   등록 채널 확인보다 더 무거운 요청입니다.** `data/tags.json`의
   `discoveryIntervalCycles` 로 실행 빈도를 조절하세요.
4. 시청자 수는 유튜브가 페이지에 노출하는 값을 그대로 가져온 것으로,
   공식 API의 `concurrentViewers`와 약간 오차가 있을 수 있습니다.
5. **워치 페이지(`/watch`, `/live`)는 GitHub Actions 러너에서 막힙니다.**
   데이터센터 IP로 라이브 워치 페이지를 열면 유튜브가 로봇 확인
   (`playabilityStatus.status = "LOGIN_REQUIRED"`)을 돌려주고 영상 정보를
   주지 않습니다. 그래서 방송 여부는 **채널 '실시간' 탭**(`/channel/<id>/streams`)
   에서 라이브 배지를 찾아 판정합니다. 채널 탭 페이지는 막히지 않습니다.
   대신 방송 시작 시각은 유튜브가 알려주는 정확한 값 대신 처음 관측한
   시각으로 기록될 수 있습니다(최대 10분 오차).

더 안정적인 방식이 필요해지면, 채널 확인 부분만 유튜브 공식
Data API v3(무료 할당량 하루 10,000 유닛)로 바꾸는 것도 고려할 수
있습니다 — 그 경우를 대비해 `scripts/common.py`의 함수 시그니처를
그대로 유지한 채 내부 구현만 API 호출로 바꾸면 나머지 코드는 그대로
씁니다.

## 화면 미리보기

`docs/index.html` 페이지는:

- 🔴 **지금 방송 중** — 등록 채널 중 라이브인 것만, 시청자 수 높은 순
- **등록 채널 중 오프라인** — 접어둔 목록, 최근 영상 정보 표시
- 🔍 **태그로 새로 발견** — 검색어에 걸린 실시간 방송, 이미 등록된
  채널이면 "등록됨" 표시
- 60초마다 자동 새로고침 (데이터 자체는 Actions가 10분마다 갱신)

`docs/history.html` 페이지(우상단 "📊 방송 이력" 버튼)는:

- **오늘 / 이번 주 / 이번 달** 누적 방송 시간 (KST 기준, 이터널리턴만/전체 토글)
- **채널별 방송 시간 표** — 등록된 채널은 방송 기록이 없어도 전부 표시됩니다
- **최근 방송 기록** — 방송 시작~종료 시각과 길이, 제목, 게임 구분

방송 시작/종료 시각은 유튜브가 페이지에 넣어주는 실제 방송 시작·종료
타임스탬프를 우선 사용하므로, 10분 간격으로 확인해도 시각이 밀리지
않습니다. 자정을 넘긴 방송은 날짜별로 쪼개서 집계합니다.

## 설정 방법

### 1. 저장소 만들고 올리기

GitHub에 새 저장소를 만들고(공개 저장소 권장 — Actions/Pages 완전 무료),
이 폴더 전체를 push 하세요.

```bash
cd youtube-streamer-tracker
git remote add origin https://github.com/<내계정>/<저장소이름>.git
git branch -M main
git add -A
git commit -m "init: 유튜브 스트리머 라이브 트래커"
git push -u origin main
```

### 2. GitHub Pages 켜기

저장소 → **Settings → Pages** → Source를 **Deploy from a branch**로,
Branch를 **main / `/docs`** 로 설정 → Save.
몇 분 뒤 `https://<내계정>.github.io/<저장소이름>/` 에서 페이지가 보입니다.

### 3. Actions 켜기 (필요하면)

저장소 → **Actions** 탭에 들어가서 워크플로 실행을 허용하라는 안내가
보이면 활성화하세요. 그다음 **"스트리머 트래킹"** 워크플로를 열고
**Run workflow** 버튼으로 한 번 수동 실행해보면, 스케줄을 기다리지 않고
바로 `docs/status.json`이 채워집니다.

### 4. 채널 등록

방법 A — 페이지에서: Pages 사이트 우상단 **"＋ 채널 등록"** 버튼 클릭 →
채널 URL/핸들 입력 → 제출. 몇 분 안에 자동으로 처리되어 이슈가 닫히고,
다음 확인 주기부터 목록에 나타납니다.

> **처리 방식(중요)**: 요청 처리는 이슈 **제목의 접두사**(`[등록]` / `[삭제]`)로
> 판단하며, 라벨에 의존하지 않습니다. GitHub은 저장소에 해당 라벨이 미리
> 만들어져 있지 않으면 이슈 폼의 `labels:` 를 조용히 무시하기 때문에,
> 라벨 조건을 쓰면 요청이 처리되지 않고 쌓이기만 합니다(실제로 겪은 문제).
> 게다가 이슈 이벤트를 놓쳐도 괜찮도록, 트래킹 워크플로가 **매 확인 주기마다
> 열려 있는 요청을 다시 훑어서(sweep)** 처리합니다. 그래서 이벤트가 유실되거나
> 워크플로가 잠깐 꺼져 있었어도 다음 주기에 반드시 반영됩니다.
> 밀린 요청을 지금 당장 처리하려면 **Actions → "요청 전체 다시 훑기 (수동)" →
> Run workflow** 를 누르세요.

방법 B — 직접 편집: `data/channels.json`에 아래 형식으로 추가 후 커밋.

```json
{ "id": "UC로시작하는24자리채널ID", "name": "표시할 이름" }
```

채널 ID는 채널 페이지에서 "정보 더보기" 또는 페이지 소스에서
`"channelId":"UC..."` 를 찾아 확인할 수 있습니다. (핸들 `@이름` 은
채널 ID가 아니므로 그대로 쓰면 안 됩니다 — 방법 A를 쓰면 이 변환을
자동으로 해줍니다.)

### 4-1. 채널 삭제

방법 A — 페이지에서(가장 간단): Pages 사이트 우상단 **"－ 채널 삭제"** 버튼을
누르면 등록된 채널이 이름순 목록으로 펼쳐집니다. 지울 채널의 **"삭제"** 를
누르면 대상이 **채널 ID로 미리 채워진** 삭제 요청이 열리므로, 그대로 제출하면
끝입니다(직접 타이핑할 필요 없음). 몇 분 안에 자동 처리되어 목록에서 사라지고
이슈가 닫힙니다. 자동 등록된 채널은 목록에 `자동` 표시가 붙습니다.

직접 입력하는 경우에도 채널 ID, 대소문자/공백 무시한 표시 이름, URL/핸들
순으로 매칭을 시도합니다.

방법 B — 직접 편집: `data/channels.json`에서 해당 채널 항목을 지우고 커밋.

### 4-2. 이터널리턴 방송 채널 자동 등록

`data/tags.json` 의 `autoRegisterDiscovered` 가 `true` 면, 태그 검색에 걸린
**미등록** 채널을 자동으로 등록합니다. 검색어에 걸렸다고 무조건 넣지 않고,
후보마다 워치 페이지를 한 번 확인해서 게임 이름이나 제목이 `gameKeywords` 와
맞을 때만 추가합니다 (예: 이터널리턴 검색에 걸린 TFT 방송은 걸러집니다).

- 채널 수 상한은 `maxChannels`(기본 60)입니다. 채널 1개당 사이클마다 요청이
  1번 늘어나므로, 상한에 도달하면 자동 추가만 멈춥니다(직접 등록은 계속 가능).
- 자동 등록된 채널은 사이트에서 `자동` 표시가 붙고, 삭제는 일반 채널과 같습니다.
- 자동 등록을 원하지 않으면 `autoRegisterDiscovered` 를 `false` 로 바꾸세요.

### 5. 검색 태그(디스커버리) 설정

`data/tags.json`에서 `queries` 목록을 수정하세요. 태그를 너무 많이
넣으면 한 번 검색 사이클이 오래 걸리니 2~4개 정도를 권장합니다.

```json
{
  "discoveryIntervalCycles": 6,
  "queries": [
    { "query": "이터널리턴", "label": "이터널리턴(한국어)" },
    { "query": "エターナルリターン", "label": "エターナルリターン(일본어)" }
  ]
}
```

## ⚠️ 스케줄 자동 실행이 꺼지는 경우

GitHub은 **저장소에 60일 동안 아무 활동(커밋 등)이 없으면 예약된(cron)
워크플로를 자동으로 비활성화**합니다. 이 트래커는 실행될 때마다
`docs/status.json`을 커밋하므로 평소엔 문제가 없지만, 만약 페이지가
오래 멈춰있다면 **Actions 탭 → 스트리머 트래킹 → 우측 "···" → Enable
workflow** 로 다시 켜주면 됩니다.

또한 GitHub Actions의 cron 스케줄은 정확히 그 분에 실행되는 것을
보장하지 않고 트래픽이 몰리면 몇 분 밀릴 수 있습니다 (공식 문서에
명시된 제약입니다). 5~10분 간격 트래킹 목적에는 충분합니다.

## 로컬에서 테스트하기

이 샌드박스/여러분의 컴퓨터에서 실제 유튜브 접속 없이 로직만
검증하려면 (합성 데이터로 만든 단위 테스트):

```bash
pip install -r requirements-dev.txt
pytest
```

실제로 값을 확인해보고 싶다면 (인터넷 되는 환경에서):

```bash
pip install -r requirements.txt
python scripts/track.py   # docs/status.json 이 갱신됩니다
```

## 파일 구조

```
.
├── data/
│   ├── channels.json   # 등록된 채널 목록 (id, name)
│   ├── tags.json       # 디스커버리 검색어 + 실행 주기
│   └── state.json      # 내부 상태(사이클 카운트 등, 손대지 않아도 됨)
│   └── history.json    # 방송 이력 원본 (진행 중/끝난 세션, 자동 갱신)
├── docs/
│   ├── index.html      # GitHub Pages로 서빙되는 라이브 현황 페이지
│   ├── history.html    # 방송 이력 페이지 (일/주/월 누적 시간)
│   ├── status.json     # track.py가 매 사이클 덮어쓰는 결과 데이터
│   └── history.json    # 이력 페이지가 읽는 집계 결과
├── scripts/
│   ├── common.py        # RSS/라이브상태/채널해석/검색 스크레이핑 함수 모음
│   ├── track.py            # 메인 실행 스크립트 (Actions가 주기적으로 실행)
│   ├── history.py          # 방송 세션 기록 + 일/주/월 집계 (순수 로직)
│   ├── process_requests.py # 열린 [등록]/[삭제] 이슈를 훑어서 처리
│   ├── resolve_channel.py  # (구) 이슈 폼 → 채널 등록 처리
│   └── remove_channel.py   # (구) 이슈 폼 → 채널 삭제 처리
├── tests/                # 합성 데이터 기반 단위 테스트 (pytest, 70개)
└── .github/
    ├── workflows/track.yml          # 10분마다: 요청 스윕 + 라이브 확인 + 이력 기록
    ├── workflows/add-channel.yml    # 이슈가 열리면 즉시 요청 처리
    ├── workflows/remove-channel.yml # 수동 실행: 밀린 요청 전체 백필
    ├── ISSUE_TEMPLATE/add-channel.yml    # 채널 등록 이슈 폼
    └── ISSUE_TEMPLATE/remove-channel.yml # 채널 삭제 이슈 폼
```

`data/history.json` 은 방송 이력 원본(진행 중 세션 + 끝난 세션)이고,
`docs/history.json` 은 페이지가 읽는 집계 결과입니다. 둘 다 Actions가
자동으로 갱신하므로 직접 수정할 필요는 없습니다.
